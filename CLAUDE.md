# ПДД-игра: 2D-игра для подготовки к теории на права

Этот файл одновременно инструкция для Артёма (как запускать работу) и техническое задание для Claude Code (что делать). Claude Code автоматически читает файл `CLAUDE.md` в корне репозитория, поэтому название файла менять не нужно.

---

## Часть 1. Для Артёма: как этим пользоваться

### Что мы делаем
Мобильную 2D-игру, в которой все вопросы из экзаменационной базы ПДД превращены в игровые ситуации. Ты ездишь на машинке по городу (вид сверху), подъезжаешь к перекрёсткам, знакам и переходам, и игра задаёт вопрос прямо в этой ситуации. Ошибся, и видишь последствия. Сюжет разбит на главы, каждая глава открывает новый район и новую тему билетов. В конце ждёт босс: настоящий экзамен как в ГИБДД.

Игра работает в браузере телефона, её можно добавить на главный экран, и она будет открываться как обычное приложение, в том числе без интернета.

### Подготовка (один раз)
1. Создай репозиторий на GitHub, например `pdd-game`.
2. Положи в корень этот файл (`CLAUDE.md`).
3. Создай папку `data/raw/` и положи туда файл с вопросами. Если картинки к вопросам лежат отдельно, положи их в `data/raw/images/`.
4. В приложении Claude открой вкладку **Code**, подключи GitHub и выбери этот репозиторий.

### Как запускать этапы
Всего 13 этапов (этапы 6–8 добавлены 28.09.2026 после выхода игры, этап 9 — 04.10.2026, этапы 10–13 — 05.10.2026). Для каждого пишешь в Claude Code одну фразу:

> Выполни этап 1 из CLAUDE.md

Дальше можно закрыть приложение. Когда вернёшься:
1. Прочитай, что Claude написал в конце сессии, и загляни в раздел «Журнал работ» внизу этого файла.
2. Открой ссылку на игру (после этапа 1 она появится в журнале) и попробуй на телефоне.
3. Если всё нравится, прими изменения (Merge pull request на GitHub).
4. Если что-то не так, напиши в той же сессии, что исправить.
5. Только после этого запускай следующий этап.

Если на каком-то этапе установка пакетов не работает, проверь в настройках окружения Claude Code, что у него есть доступ к сети.

## Часть 2. Для Claude Code: техническое задание

### Главные правила (действуют на всех этапах)
1. **Все вопросы только из файла.** Никогда не придумывай вопросы, варианты ответов, правильные ответы или пояснения. Текст вопроса, варианты и правильный ответ берутся из `data/questions.json` без изменений по смыслу. Пояснений в исходном PDF нет, поэтому они берутся из открытого набора pdd_russia (`data/raw/pdd_russia/`, см. `SOURCE.md`). Пояснение подключается к вопросу, только если в наборе у этого вопроса тот же правильный ответ, что и в PDF, и в игре рядом с пояснением указан источник.
2. **100% покрытие.** Каждый вопрос из базы должен быть в игре ровно один раз как основная точка встречи (в режиме «работа над ошибками» и на экзамене он может повторяться). Скрипт `npm run coverage` должен проходить без ошибок в конце каждого этапа начиная со 2-го.
3. **2D-сцена иллюстрирует, а не заменяет.** Игровая сцена создаёт контекст, но в момент вопроса игрок всегда видит оригинальный текст вопроса, оригинальную картинку билета (если есть) и оригинальные варианты. Так ответы никогда не расходятся с официальными.
4. **Телефон в приоритете.** Портретная ориентация, управление одним пальцем, крупные кнопки (от 48px), плавная работа на недорогих Android-телефонах.
5. **Журнал.** В конце каждого этапа допиши в раздел «Журнал работ» ниже: что сделано, что не получилось, ссылку на игру, число покрытых вопросов.
6. **Не выходи за рамки этапа.** Делай только текущий этап. Идеи на будущее записывай в журнал.

### Технологии
- TypeScript + Vite
- Phaser 3 для 2D-игры
- PWA (manifest + service worker): установка на главный экран, работа офлайн
- Сохранение прогресса в `localStorage` (с защитой try/catch)
- Деплой на GitHub Pages через GitHub Actions при каждом пуше в `main`
- Графика: простой векторный или пиксельный стиль, генерируется кодом или рисуется в SVG. Никаких чужих персонажей и логотипов.

### Формат данных
`data/questions.json`, массив объектов:
```json
{
  "id": "B12-Q07",
  "ticket": 12,
  "number": 7,
  "text": "Текст вопроса",
  "image": "images/b12q07.jpg",
  "options": ["Вариант 1", "Вариант 2", "Вариант 3"],
  "correct": 1,
  "explanation": "Пояснение к ответу из data/raw/pdd_russia, если есть",
  "topic": "Проезд перекрёстков"
}
```
`data/mapping.json` описывает, где в игре встречается каждый вопрос: глава, тип сцены (или мини-игры) и параметры сцены.

### Этап 1. Фундамент и данные
**Цель:** вопросы превращены в чистые данные, у игры есть каркас и ссылка, которая открывается на телефоне.

1. Изучи файл в `data/raw/`, определи формат и напиши скрипт `scripts/import.ts`, который создаёт `data/questions.json` по схеме выше. Картинки скопируй в `public/images/`.
2. Напиши скрипт проверки: у каждого вопроса есть текст, минимум 2 варианта, правильный ответ в допустимых пределах, существующая картинка (если указана). Выведи отчёт: сколько вопросов, сколько с картинками, какие с ошибками.
3. Если в файле есть темы, используй их. Если нет, распредели вопросы по темам по их содержанию и отметь в журнале, что темы определены автоматически.
4. Создай проект Vite + TypeScript + Phaser, настрой PWA и деплой на GitHub Pages.
5. Сделай стартовый экран с названием игры и простой временный режим «пройти вопрос», чтобы проверить, что данные читаются правильно.

**Готово, когда:** ссылка открывается на телефоне, игра ставится на главный экран, отчёт импорта показывает все вопросы без потерь.

### Этап 2. Движок мира
**Цель:** можно ездить по городу, и на точках интереса появляются ситуации с вопросами.

1. Карта города с видом сверху: дороги, перекрёстки, тротуары, здания. Одна тестовая карта-район.
2. Машина игрока. Управление: касание точки на дороге (машина едет туда) или виртуальный джойстик; выбор в настройках.
3. Система шаблонов сцен. Каждый шаблон собирает ситуацию из параметров. Минимальный набор: регулируемый перекрёсток, нерегулируемый перекрёсток (равнозначный и неравнозначный), круговое движение, пешеходный переход, остановка общественного транспорта, железнодорожный переезд, обгон и встречный разъезд, стоянка и остановка, знаки и разметка на прямом участке, движение по автомагистрали, темное время суток и погода.
4. Точка интереса: игрок подъезжает, машина плавно останавливается, сцена оживает (другие машины, пешеходы, светофор), поверх появляется карточка вопроса по правилу 3.
5. Последствия ответа: правильно, и машина проезжает дальше с короткой анимацией; неправильно, и показывается анимация последствия (штраф, помеха, инспектор), затем пояснение и правильный ответ.
6. Скрипт `npm run coverage`: сравнивает `questions.json` и `mapping.json` и падает, если какой-то вопрос не размещён или размещён дважды.

**Готово, когда:** на тестовой карте работают все шаблоны сцен хотя бы на одном вопросе каждый.

### Этап 3. Все вопросы в игре
**Цель:** каждый из всех вопросов базы размещён в игре.

1. Пройди по всем вопросам и заполни `mapping.json`: подходящий шаблон сцены и его параметры.
2. Для вопросов, которые не показать на дороге, сделай мини-игры:
   - «Аптечка»: первая помощь, игрок выбирает действия в правильном порядке через варианты из билета.
   - «Инспектор»: ответственность и штрафы, диалог с инспектором.
   - «Гараж»: техническое состояние машины, игрок осматривает авто и отвечает.
   - «Общие положения»: термины и определения, быстрая викторина в кабинете автошколы.
3. Распредели вопросы по главам-районам (по темам), примерно равными порциями.
4. Прогони `npm run coverage` и приложи результат в журнал.

**Готово, когда:** покрытие 100%, каждый вопрос можно встретить в игре.

### Этап 4. Сюжет и прогресс
**Цель:** игра становится историей, а не набором вопросов.

1. Сюжет: игрок новичок, только получивший ученическую машину, подрабатывает курьером в вымышленном городе. У каждой главы короткое вступление и финал, свой район и своё задание (доставить посылку через весь центр, успеть на вокзал и т. д.). Персонажи вымышленные: наставник-инструктор, диспетчер, инспектор.
2. Главы открываются по очереди. Чтобы открыть следующую, нужно пройти точки текущей с результатом от 80%.
3. Очки опыта, уровни водителя, звёзды за главу.
4. «Работа над ошибками»: вопросы, где игрок ошибся, возвращаются чаще (интервальное повторение: ошибка, повтор через 1 день, 3 дня, 7 дней). Отдельный режим «Разбор ошибок» в меню.
5. Экран прогресса: сколько вопросов пройдено из общего числа, по каждой теме процент правильных, слабые темы.

**Пожелание Артёма (27.09.2026), обязательно к выполнению:** сюжет должен быть по-настоящему большим, а его прохождение до конца — означать готовность к экзамену на 100%. Поэтому:
- сюжет проводит игрока через все 800 вопросов базы, ни одна тема не остаётся «за кадром»;
- финал сюжета недоступен, пока каждый вопрос не отвечен верно и все ошибки не закреплены повторами (1, 3 и 7 дней из п. 4), то есть пока в «Работе над ошибками» не осталось вопросов;
- перед финалом — контрольные билеты, которые нужно пройти без ошибок; финал сюжета ведёт к экзамену-боссу этапа 5;
- у каждой главы своя история, персонажи возвращаются из главы в главу, у сюжета есть общая линия от первого дня за рулём до экзамена.

**Готово, когда:** можно пройти первую главу от начала до конца с сюжетом, а прогресс сохраняется после закрытия игры.

### Этап 5. Экзамен-босс и полировка
**Цель:** финальная проверка знаний и готовая к ежедневному использованию игра.

1. Режим «Экзамен» по действующим правилам ГИБДД: 20 случайных вопросов, 20 минут. При 1–2 ошибках в разных блоках добавляется по 5 вопросов на каждую ошибку, дополнительное время, и в дополнительных вопросах ошибаться нельзя. Две ошибки в одном блоке или три и более означают провал. Перед реализацией проверь, что правила в коде совпадают с этим описанием, и отметь в журнале, если что-то пришлось уточнить.
2. Экзамен открывается как финальный босс после всех глав, а в меню доступен всегда как тренировка.
3. Звуки (с выключателем), вибрация на ошибку (с выключателем), короткое обучение при первом запуске.
4. Проверка производительности на мобильном экране, исправление ошибок, финальный прогон `npm run coverage`.

**Готово, когда:** игру можно пройти полностью, экзамен работает, покрытие 100%.

### Этап 6. Удержание и надёжность
**Цель:** в игру хочется возвращаться каждый день, а прогресс не теряется.

1. Сохранение прогресса в файл и восстановление из файла (прогресс, история билетов и экзаменов, настройки). Перед восстановлением — предупреждение, что текущий прогресс заменится; испорченный или чужой файл не должен ломать игру.
2. «Готовность к экзамену: N%» на главном экране — оценка по статистике игрока: доля освоенных вопросов, слабые блоки билета, ошибки на повторе, результаты экзаменов. Рядом — что сделать, чтобы готовность выросла.
3. Серия дней подряд и цель на день (например, «сегодня: 10 повторов» или «3 точки»). Если повторов на сегодня нет, цель подбирается из текущей главы.
4. Монеты за верные ответы и покраска и наклейки на машину курьера (только внешний вид, на правила и ответы не влияет). Выбранная раскраска видна в городе и в меню.
5. Картинка-результат, чтобы поделиться с друзьями: сданный экзамен, пройденная глава, уровень. Кнопка «Поделиться» (на телефоне — системное меню, иначе — сохранить картинку).
6. Крупный шрифт и тёмная тема в настройках.

**Готово, когда:** прогресс можно сохранить в файл и восстановить на другом телефоне, на главном экране видны готовность, серия и цель дня, машину можно перекрасить за монеты.

### Этап 7. Живой город
**Цель:** езда между точками становится интересной, а не просто дорогой к следующему вопросу.

1. Машины и пешеходы между точками: по улицам района ездит поток, пешеходы идут по тротуарам и переходам. Они соблюдают правила и не мешают игроку проехать.
2. Звуки города: шум мотора, зависящий от скорости, фон улицы (с выключателем звуков из этапа 5).
3. Случайные события в пути: сзади скорая с сиреной, на дорогу выкатился мяч, сменилась погода. Событие может задать вопрос из базы по своей теме (правило 3: оригинальная карточка вопроса); размещение вопросов в `mapping.json` при этом не меняется.
4. Гонка с Артёмом: в каждой главе соперник доставляет свою посылку, в конце главы видно, кто быстрее и точнее.
5. Выборы в диалогах и побочные задания от персонажей (помочь Артёму с мопедом, отвезти пирожки Галины Ивановны и т. п.), с небольшими наградами.

**Готово, когда:** в каждом районе есть поток машин и пешеходов, в пути случаются события, в главах есть гонка с Артёмом и хотя бы одно побочное задание.

### Этап 8. Правила за рулём
**Цель:** игрок не только отвечает на вопросы, но и сам соблюдает правила, когда ведёт машину.

1. Город замечает нарушения игрока: проезд на красный, непропущенный пешеход на переходе, превышение скорости, движение по встречной, остановка там, где нельзя. Каждое нарушение проверяется по понятному правилу в коде и покрыто тестами.
2. За нарушение машину останавливает лейтенант Соколов: короткая сцена и вопрос из базы именно про это правило (оригинальная карточка, правило 3). Ошибка уходит в работу над ошибками.
3. Счётчик «Чистая езда»: сколько проехано без нарушений; бонус к опыту и звёздам главы за аккуратную езду.
4. Настройка сложности: новичкам — подсказки перед нарушением (например, мигающий светофор впереди), опытным — без подсказок.

**Готово, когда:** нарушения на светофоре, переходе и по скорости замечаются во всех районах, за каждое задаётся подходящий вопрос из базы, «Чистая езда» влияет на награды главы.

### Этап 9. Мой экзамен
**Цель:** игра готовит к экзамену в ГИБДД к конкретной дате (идея выбрана Артёмом 04.10.2026).

1. Игрок указывает дату своего экзамена в ГИБДД (её можно изменить или убрать).
2. План на каждый день готовит заранее, а не ровно к дате (уточнение Артёма 04.10.2026: «чтобы последние дни/недели он просто повторял уже пройденное, чтобы точно ничего не забыть»). Сначала учёба: все новые вопросы, не меньше 20 в день, до начала закрепления. Потом закрепление: новых вопросов нет, каждый день повторение пройденного (сначала вопросы и темы, где были ошибки, потом давно не встречавшиеся), повторы ошибок и пробные экзамены. План на день — это цель дня (этап 6): выполнил всё — монеты и серия.
3. Повторы ошибок сжимаются под дату: три повтора по-прежнему нужны, но промежутки короче, чтобы все повторы успели до экзамена. Без даты — как раньше, через 1, 3 и 7 дней.
4. Прогноз: успеваешь или нет. Если не успеваешь — честно сказать, что делать в первую очередь.
5. После даты экзамена игра спрашивает, сдан ли экзамен, и запоминает результат вместе с готовностью в тот день: так видно, насколько готовность совпадает с настоящим экзаменом.

**Готово, когда:** с датой экзамена видно план на сегодня и прогноз, повторы успевают до экзамена, а результат настоящего экзамена сохраняется.

### Этапы 10–13. Новые режимы (идеи выбраны Артёмом 05.10.2026)
Общее для этапов 10–13: в меню появляется кнопка «Режимы» с четырьмя карточками новых режимов. Все режимы работают без сервера и без интернета (кроме отправки ссылки другу). Вопросы — только из базы и в оригинальной карточке (правила 1 и 3), ответы идут в прогресс и в работу над ошибками, как в билетах.

### Этап 10. Дуэль
**Цель:** вызвать друга по ссылке и сравнить, кто лучше знает правила.

1. Новая дуэль: 10 случайных вопросов из базы, как на экзамене — без подсказки, верен ли ответ; считаются верные ответы и время.
2. Ссылка-вызов и QR-код: в ссылке зашифрованы вопросы, имя и результат игрока, сервер не нужен. Отправка через системное меню «Поделиться», иначе ссылка копируется.
3. Друг открывает ссылку, видит вызов («8 из 10 за 2:13 — сможешь лучше?»), отвечает на те же 10 вопросов и видит сравнение: кто победил, кто как ответил на каждый вопрос, разбор с пояснениями.
4. Ответ: ссылка с обоими результатами, чтобы автор вызова тоже увидел итог. Ответный вызов — новая дуэль на других вопросах.
5. История дуэлей: победы, поражения, ничьи. Испорченная или чужая ссылка не ломает игру.

**Готово, когда:** вызов, ответ и итог проходят по ссылке между двумя телефонами без сервера.

### Этап 11. Знакодекс
**Цель:** альбом дорожных знаков, который хочется собрать целиком.

1. В альбоме — все знаки, которые есть в билетах (по разметке сцен `data/scenes.json`). Названия, картинки и описания знаков — из открытого набора pdd_russia (`signs/signs.json`), с указанием источника; ничего не придумывается.
2. Знак открывается, когда верно отвечен вопрос, в котором он есть. Закрытый знак показывает, в скольких вопросах встречается, и кнопку «Найти» — тренировку этих вопросов.
3. Редкость: знак из одного вопроса — редкий, из 2–3 — необычный, из 4 и больше — обычный.
4. Группы знаков (предупреждающие, приоритета и т. д.) с прогрессом. Собранная группа — монеты, собранные группы открывают новые наклейки на машину.
5. Новый знак отмечается сообщением сразу после ответа — в городе, в билетах, на экзамене, в дуэли.

**Готово, когда:** в альбоме видны все знаки из билетов, знаки открываются верными ответами, за собранные группы дают награды.

### Этап 12. Один день Соколова
**Цель:** посмотреть на правила глазами инспектора.

1. Игрок в машине ДПС у регулируемого перекрёстка района. Машины потока иногда нарушают: проезжают на красный, превышают скорость, останавливаются там, где нельзя. Нарушение проверяется тем же модулем правил, что и у игрока (этап 8).
2. Касание нарушителя — «Поймал!», машина прижимается к обочине, игрок отвечает на вопрос из базы именно про это правило (оригинальная карточка). Касание добросовестного водителя — ошибка.
3. Смена длится 3 минуты: пойманные, пропущенные и ошибочные остановки, верные ответы, рекорд.

**Готово, когда:** в смене встречаются нарушения трёх видов, их можно поймать касанием, за каждое задаётся вопрос по правилу.

### Этап 13. Смена курьера
**Цель:** быстрый режим на 5 минут, в который хочется возвращаться после сюжета.

1. Район любой открытой главы, 5 минут. Цель доставки появляется на карте; доехал — вопрос из базы (сначала повторы ошибок, потом слабые и новые вопросы).
2. Верный ответ — очки и множитель серии (до ×5), ошибка — множитель сбрасывается и минус время, нарушение правил — минус время.
3. Итог: очки, доставки, точность, таблица рекордов на телефоне.
4. Трейлер игры (HyperFrames) пересобран с новыми режимами: не отдельный ролик об изменениях, а один общий трейлер (уточнение Артёма 05.10.2026).

**Готово, когда:** смену можно сыграть от начала до конца в любом открытом районе, рекорды сохраняются, трейлер обновлён.
