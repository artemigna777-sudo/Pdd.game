# ПДД-игра: 2D-игра для подготовки к теории на права

Этот файл одновременно инструкция для Артёма (как запускать работу) и техническое задание для Claude Code (что делать). Claude Code автоматически читает файл `CLAUDE.md` в корне репозитория, поэтому название файла менять не нужно.

---

## Часть 1. Для Артёма: как этим пользоваться

### Что мы делаем
Мобильную 2D-игру, в которой все вопросы из экзаменационной базы ПДД превращены в игровые ситуации. Ты ездишь на машинке по городу (вид сверху), подъезжаешь к перекрёсткам, знакам и переходам, и игра задаёт вопрос прямо в этой ситуации. Ошибся, и видишь последствия. Сюжет разбит на главы, каждая глава открывает новый район и новую тему билетов. В конце ждёт босс: настоящий экзамен как в ГИБДД.

Игра работает в браузере телефона, её можно добавить на главный экран, и она будет открываться как обычное приложение, в том числе без интернета.

### Подготовка (один раз)
1. Создай репозиторий на GitHub, например `pdd-game`.
2. Положи в корень этот файл (`CLAUDE.md`).
3. Создай папку `data/raw/` и положи туда файл с вопросами. Если картинки к вопросам лежат отдельно, положи их в `data/raw/images/`.
4. В приложении Claude открой вкладку **Code**, подключи GitHub и выбери этот репозиторий.

### Как запускать этапы
Всего 5 этапов. Для каждого пишешь в Claude Code одну фразу:

> Выполни этап 1 из CLAUDE.md

Дальше можно закрыть приложение. Когда вернёшься:
1. Прочитай, что Claude написал в конце сессии, и загляни в раздел «Журнал работ» внизу этого файла.
2. Открой ссылку на игру (после этапа 1 она появится в журнале) и попробуй на телефоне.
3. Если всё нравится, прими изменения (Merge pull request на GitHub).
4. Если что-то не так, напиши в той же сессии, что исправить.
5. Только после этого запускай следующий этап.

Если на каком-то этапе установка пакетов не работает, проверь в настройках окружения Claude Code, что у него есть доступ к сети.

## Часть 2. Для Claude Code: техническое задание

### Главные правила (действуют на всех этапах)
1. **Все вопросы только из файла.** Никогда не придумывай вопросы, варианты ответов, правильные ответы или пояснения. Текст вопроса, варианты и правильный ответ берутся из `data/questions.json` без изменений по смыслу. Пояснений в исходном PDF нет, поэтому они берутся из открытого набора pdd_russia (`data/raw/pdd_russia/`, см. `SOURCE.md`). Пояснение подключается к вопросу, только если в наборе у этого вопроса тот же правильный ответ, что и в PDF, и в игре рядом с пояснением указан источник.
2. **100% покрытие.** Каждый вопрос из базы должен быть в игре ровно один раз как основная точка встречи (в режиме «работа над ошибками» и на экзамене он может повторяться). Скрипт `npm run coverage` должен проходить без ошибок в конце каждого этапа начиная со 2-го.
3. **2D-сцена иллюстрирует, а не заменяет.** Игровая сцена создаёт контекст, но в момент вопроса игрок всегда видит оригинальный текст вопроса, оригинальную картинку билета (если есть) и оригинальные варианты. Так ответы никогда не расходятся с официальными.
4. **Телефон в приоритете.** Портретная ориентация, управление одним пальцем, крупные кнопки (от 48px), плавная работа на недорогих Android-телефонах.
5. **Журнал.** В конце каждого этапа допиши в раздел «Журнал работ» ниже: что сделано, что не получилось, ссылку на игру, число покрытых вопросов.
6. **Не выходи за рамки этапа.** Делай только текущий этап. Идеи на будущее записывай в журнал.

### Технологии
- TypeScript + Vite
- Phaser 3 для 2D-игры
- PWA (manifest + service worker): установка на главный экран, работа офлайн
- Сохранение прогресса в `localStorage` (с защитой try/catch)
- Деплой на GitHub Pages через GitHub Actions при каждом пуше в `main`
- Графика: простой векторный или пиксельный стиль, генерируется кодом или рисуется в SVG. Никаких чужих персонажей и логотипов.

### Формат данных
`data/questions.json`, массив объектов:
```json
{
  "id": "B12-Q07",
  "ticket": 12,
  "number": 7,
  "text": "Текст вопроса",
  "image": "images/b12q07.jpg",
  "options": ["Вариант 1", "Вариант 2", "Вариант 3"],
  "correct": 1,
  "explanation": "Пояснение к ответу из data/raw/pdd_russia, если есть",
  "topic": "Проезд перекрёстков"
}
```
`data/mapping.json` описывает, где в игре встречается каждый вопрос: глава, тип сцены (или мини-игры) и параметры сцены.

### Этап 1. Фундамент и данные
**Цель:** вопросы превращены в чистые данные, у игры есть каркас и ссылка, которая открывается на телефоне.

1. Изучи файл в `data/raw/`, определи формат и напиши скрипт `scripts/import.ts`, который создаёт `data/questions.json` по схеме выше. Картинки скопируй в `public/images/`.
2. Напиши скрипт проверки: у каждого вопроса есть текст, минимум 2 варианта, правильный ответ в допустимых пределах, существующая картинка (если указана). Выведи отчёт: сколько вопросов, сколько с картинками, какие с ошибками.
3. Если в файле есть темы, используй их. Если нет, распредели вопросы по темам по их содержанию и отметь в журнале, что темы определены автоматически.
4. Создай проект Vite + TypeScript + Phaser, настрой PWA и деплой на GitHub Pages.
5. Сделай стартовый экран с названием игры и простой временный режим «пройти вопрос», чтобы проверить, что данные читаются правильно.

**Готово, когда:** ссылка открывается на телефоне, игра ставится на главный экран, отчёт импорта показывает все вопросы без потерь.

### Этап 2. Движок мира
**Цель:** можно ездить по городу, и на точках интереса появляются ситуации с вопросами.

1. Карта города с видом сверху: дороги, перекрёстки, тротуары, здания. Одна тестовая карта-район.
2. Машина игрока. Управление: касание точки на дороге (машина едет туда) или виртуальный джойстик; выбор в настройках.
3. Система шаблонов сцен. Каждый шаблон собирает ситуацию из параметров. Минимальный набор: регулируемый перекрёсток, нерегулируемый перекрёсток (равнозначный и неравнозначный), круговое движение, пешеходный переход, остановка общественного транспорта, железнодорожный переезд, обгон и встречный разъезд, стоянка и остановка, знаки и разметка на прямом участке, движение по автомагистрали, темное время суток и погода.
4. Точка интереса: игрок подъезжает, машина плавно останавливается, сцена оживает (другие машины, пешеходы, светофор), поверх появляется карточка вопроса по правилу 3.
5. Последствия ответа: правильно, и машина проезжает дальше с короткой анимацией; неправильно, и показывается анимация последствия (штраф, помеха, инспектор), затем пояснение и правильный ответ.
6. Скрипт `npm run coverage`: сравнивает `questions.json` и `mapping.json` и падает, если какой-то вопрос не размещён или размещён дважды.

**Готово, когда:** на тестовой карте работают все шаблоны сцен хотя бы на одном вопросе каждый.

### Этап 3. Все вопросы в игре
**Цель:** каждый из всех вопросов базы размещён в игре.

1. Пройди по всем вопросам и заполни `mapping.json`: подходящий шаблон сцены и его параметры.
2. Для вопросов, которые не показать на дороге, сделай мини-игры:
   - «Аптечка»: первая помощь, игрок выбирает действия в правильном порядке через варианты из билета.
   - «Инспектор»: ответственность и штрафы, диалог с инспектором.
   - «Гараж»: техническое состояние машины, игрок осматривает авто и отвечает.
   - «Общие положения»: термины и определения, быстрая викторина в кабинете автошколы.
3. Распредели вопросы по главам-районам (по темам), примерно равными порциями.
4. Прогони `npm run coverage` и приложи результат в журнал.

**Готово, когда:** покрытие 100%, каждый вопрос можно встретить в игре.

### Этап 4. Сюжет и прогресс
**Цель:** игра становится историей, а не набором вопросов.

1. Сюжет: игрок новичок, только получивший ученическую машину, подрабатывает курьером в вымышленном городе. У каждой главы короткое вступление и финал, свой район и своё задание (доставить посылку через весь центр, успеть на вокзал и т. д.). Персонажи вымышленные: наставник-инструктор, диспетчер, инспектор.
2. Главы открываются по очереди. Чтобы открыть следующую, нужно пройти точки текущей с результатом от 80%.
3. Очки опыта, уровни водителя, звёзды за главу.
4. «Работа над ошибками»: вопросы, где игрок ошибся, возвращаются чаще (интервальное повторение: ошибка, повтор через 1 день, 3 дня, 7 дней). Отдельный режим «Разбор ошибок» в меню.
5. Экран прогресса: сколько вопросов пройдено из общего числа, по каждой теме процент правильных, слабые темы.

**Готово, когда:** можно пройти первую главу от начала до конца с сюжетом, а прогресс сохраняется после закрытия игры.

### Этап 5. Экзамен-босс и полировка
**Цель:** финальная проверка знаний и готовая к ежедневному использованию игра.

1. Режим «Экзамен» по действующим правилам ГИБДД: 20 случайных вопросов, 20 минут. При 1–2 ошибках в разных блоках добавляется по 5 вопросов на каждую ошибку, дополнительное время, и в дополнительных вопросах ошибаться нельзя. Две ошибки в одном блоке или три и более означают провал. Перед реализацией проверь, что правила в коде совпадают с этим описанием, и отметь в журнале, если что-то пришлось уточнить.
2. Экзамен открывается как финальный босс после всех глав, а в меню доступен всегда как тренировка.
3. Звуки (с выключателем), вибрация на ошибку (с выключателем), короткое обучение при первом запуске.
4. Проверка производительности на мобильном экране, исправление ошибок, финальный прогон `npm run coverage`.

**Готово, когда:** игру можно пройти полностью, экзамен работает, покрытие 100%.
